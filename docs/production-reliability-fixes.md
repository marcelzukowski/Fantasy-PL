# Production reliability fixes

Scope: audit A02 (saved Comparator results), A01 (scientific worker startup), and A06 (Market Shadow status). Mathematical scoring, production V22/V3/Chip, terminal FT, legality, read-only accounts and experimental solver isolation are unchanged.

Saved scenarios retain their selections even when stored result fields are missing, corrupt or inconsistent. All native scenario/HOLD/production paths must reconcile objective, hits, terminal FT, deltas and XI/captain/transfer identities before an evaluated score can be reused. Current context ID and full native input digest remain mandatory. Invalid or stale results explain that re-evaluation is needed; reconstructing selections uses current canonical validation. Reads do not rewrite old files. Renaming a scenario preserves its original result payload; production Decision reports are never modified. These checks detect structural/arithmetic corruption, not deliberately coordinated malicious changes, and do not rerun native scoring on every display.

Decision/Chip FailedToStart now explicitly finishes the workflow because Qt does not emit finished for that error. Missing Python during Chip preparation moves a chained workflow to PARTIAL, keeping the previous Decision. Logs retain launch diagnostics and dependency errors; retry works without restarting the GUI. Comparator busy state and handshake timer are installed before start, so a synchronous launch failure cannot overwrite cleanup. Structured initialization errors stop the owned worker immediately and retain their explanation; final output is drained before handling exit. Its existing handshake deadline/cancel/owned-worker guard remains in use.

Market status comes from the canonical selected-run sidecar before legacy manifest fallback. Supported v2 identity, season/GW, model cutoff, simulator/config metadata, influence=false, coverage and observation/PIT timestamps are validated. Invalid content is UNAVAILABLE; incompatible inputs are STALE; explicit FAILED/SKIPPED become FAILED/NOT_RUN. Successful current observations are COMPLETED or PARTIAL; the producer's ten-minute snapshot window distinguishes a stale previous completion. Both model and market cutoffs are shown, and a later observation is explicitly advisory rather than report-time evidence. Explicit manifest RUNNING/NOT_RUN/FAILED is displayed only when recorded; filesystem age never invents RUNNING. Legacy manifest coverage without a verifiable observation cutoff is labelled unverified. No market weights or provider calls change.
